{% comment %} Whole-game analysis, and the page's only two controls. Nothing queues analysis on a schedule — an imported archive is far more games than a worker could ever get through — so this is where it starts. The POST is idempotent (`enqueue_game_analysis` skips what is already queued or done), so a second press costs nothing. Once every move is analysed the button turns into a re-run: the same endpoint with `force=1`. Nothing polls. The state is whatever the database said when this fragment was rendered, and Refresh is how the user asks again — which is also what runs the stuck-analysis sweeps, in `views.game_position`. The state line says which of three things is true and no more: a count that only moves when you press a button reads as a stalled count. The third state — nothing queued, something still un-analysed — is both the game nobody has analysed yet and the game with a move the coach gave up on, and the plain button is the way out of either: the service re-queues a FAILED row without `force`. {% endcomment %} {% if analysis_total %}
